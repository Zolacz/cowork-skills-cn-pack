# paper-drafter · 论文阅读与起草 Skill

## 设计目标

把"看一堆 PDF → 一边看一边记 → 拼成一篇综述 / 研究笔记 / 引言段落"这件长链推理任务，封装成可复用的工作流。

针对的真实痛点：

- 一次要消化 5–20 篇论文，**记忆碎片**散在各 PDF 里，写到第三篇就忘了第一篇说了什么
- 文献阅读的"提炼摘要"和"综述写作的论证组织"是两个不同任务，混在一起做就**两边都不好**
- 中文论文写作有特定格式要求（中文标点、半角全角、引文格式），通用 LLM 经常**形式不达标**

## 触发判断

| 用户说 | 触发模式 |
|---|---|
| "帮我读完这篇 PDF 写个 5 行总结" | 单篇精读模式 |
| "把这 5 篇论文做个对比" | 横向对比模式 |
| "我要写一篇 RLHF 的综述，先帮我整理文献" | 综述起草模式 |
| "把方法部分单独提出来对比" | 字段提取模式 |
| "写一段引言，参考这 3 篇" | 引文写作模式 |

## 工作流

### Step 1 · 入库：每篇论文做一次结构化提取

对每个 PDF，提取以下字段并存为一个 YAML：

```yaml
id: <作者首字母+年份>     # e.g. zhang2024
title: ...
authors: [...]
venue: ...                # 期刊/会议
year: 2024
contribution: |
  （3-5 行，用论文自己的话总结核心贡献）
method: |
  （技术路线，含关键数据）
results: |
  （量化结果，要数字）
limitations: |
  （论文自陈的 + 我读出来的）
relevance_to_my_topic: |
  （和当前正在做的事情有什么关联）
my_questions:
  - 问题 1
  - 问题 2
bibtex: |
  @article{zhang2024,
    ...
  }
```

每篇用 `scripts/extract_paper.py` 处理 PDF → 结构化 YAML，存到 `./.papers/<id>.yaml`。

**关键技巧**：每篇在独立子任务里处理（Task tool 派发），主上下文只回收文件名。读 5 篇论文的中间状态不会污染主对话。

### Step 2 · 检索：基于已入库论文做查询

用户问"哪几篇提到了 PPO 的 KL 约束？"时，先读 `./.papers/*.yaml`，按字段命中检索，不再触碰原始 PDF。

### Step 3 · 起草：分段产出

根据用户的写作目标，调用对应的模板：

- **综述**：`templates/literature_review.md`
- **引言**：`templates/introduction.md`
- **方法对比表**：`templates/method_table.md`
- **研究笔记**：`templates/research_note.md`

每段产出后，**追加引文编号** `[id1, id2]`，最终阶段统一替换为 BibTeX key 或正式编号。

## 中文学术格式约束

默认遵守以下规范（除非用户明确要求改变）：

- 中文标点：「，。：；！？」"《》"
- 数字、英文术语保持半角，中英文之间加空格
- 引文格式：[1][2,3] 上标编号，参考文献节用 GB/T 7714
- 不使用第一人称单数（"我认为"），用 "本文 / 本研究"
- 段落首行不缩进（屏幕阅读习惯），但导出 .docx 时通过 `docx` skill 添加首行缩进

## 与 docx / pdf skill 的协同

| 场景 | 协同 skill |
|---|---|
| 输入 PDF 抽取文本 | `pdf` skill |
| 输出 .docx 论文草稿 | `docx` skill（首行缩进、宋体小四、参考文献样式） |
| 输出 .pdf 终稿 | `pdf` skill |
| 表格对比 | 直接 markdown，复杂表用 `xlsx` skill 然后 import |

## 脚本

| 脚本 | 作用 |
|---|---|
| `scripts/extract_paper.py` | PDF → 结构化 YAML（首页 metadata + 全文索引） |
| `scripts/search_papers.py` | 在已入库 YAML 中按字段 / 全文检索 |
| `scripts/cite_normalize.py` | 把 `[id1,id2]` 占位替换为 [1][2] 数字编号 |

## 反例

- ❌ 一次性把 5 篇 PDF 全文塞进主上下文（会爆 + 互相污染）
- ❌ 在没读完论文时就开始写综述（必须先入库再起草）
- ❌ 直接搬论文原话（会触发版权问题，必须复述）
