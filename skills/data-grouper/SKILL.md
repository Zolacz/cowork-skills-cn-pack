# data-grouper · 数据智能分类与质量 Skill

## 设计目标

很多人手里有一份"长得乱七八糟"的表：客户名单、问卷、商品列表、订单流水。
通用 LLM 处理这种任务很容易**幻觉**（把没有的字段填进去），这个 skill 把流程结构化，让幻觉无处可藏。

## 触发场景

| 场景 | 例子 |
|---|---|
| 客户/联系人去重 | "这两份名单合并去重" |
| 商品归类 | "给这个商品列表打三级类目" |
| 订单异常检测 | "找出可能是刷单的订单" |
| 问卷开放题编码 | "把这 800 条问卷答案归类" |
| 数据脱敏 | "把这份表里的手机号、身份证打码" |

## 工作流

### Step 1 · 探查表结构（不读全表）

调用 `xlsx` / 直接 pandas 读前 100 行，输出：

```
表: customers.xlsx (sheet: 'Sheet1')
行数: 12,438
列:
  - id        int64    null=0%   sample=[10001, 10002, 10003]
  - name      object   null=0.2% sample=['张三', '李四公司', '王某']
  - phone     object   null=15%  sample=['13800001111', '13900002222', '021-12345678']
  - city      object   null=8%   sample=['北京', '北京市', 'Beijing']  ⚠ 多种写法
  - level     object   null=22%  sample=['VIP', 'vip', '普通', None]   ⚠ 大小写不一致
```

**关键**：标注出可疑字段（多写法、大小写、null 高、明显脏）——这是后续清洗的优先级。

### Step 2 · 与用户对齐目标

不读全部数据就直接动手 = 灾难。先确认：

- 你想要的输出是？（新增哪些列、产出哪个文件）
- 关键字段的"标准化规则"？（如 city = 都用"北京"还是"北京市"）
- 异常的判定标准？（如 phone 不是 11 位算异常吗？还是算座机？）

### Step 3 · 分批处理（不爆上下文）

对每一批 100–500 行：

- 子任务（Task tool）：读这批 → 输出新增列 → 写回 csv
- 主任务只持有进度 + 异常累计

### Step 4 · 输出三件套

```
output/
├── customers_labeled.xlsx   # 原表 + 新增列
├── quality_report.md        # 质量报告
└── changes_log.csv          # 每行做了什么改动（审计用）
```

quality_report.md 模板（中文）：

```markdown
# 数据质量报告 — customers.xlsx

## 基本统计
- 输入行数: 12,438
- 输出行数: 12,401（删去 37 个完全空行）
- 处理耗时: 4.2 分钟

## 字段问题分布
| 字段 | 问题类型 | 数量 | 处理方式 |
|---|---|---:|---|
| city | 写法不一致 | 1,120 | 统一为标准名 |
| phone | 长度不符 | 88 | 标记为 phone_invalid=True |
| level | 大小写 | 340 | 统一为大写 |

## 异常样本（抽 5 条供人工核对）
…

## 后续建议
1. 在 ETL 入口加 city 校验
2. phone 字段建议改用 BIGINT 存
```

## 中文数据特有规则

- 姓名：保留原写法，**不要**自作聪明拆姓和名
- 公司名：合并 "有限公司" / "（有限公司）" / "公司" 这类后缀差异时要询问
- 地址：城市级别去重容易，街道地址不要做模糊合并
- 手机号：11 位 1 开头；如果是 +86 / 86 前缀，转成 11 位
- 身份证：脱敏只露前 6 + 后 4

## 脚本

| 脚本 | 作用 |
|---|---|
| `scripts/profile_table.py` | 读前 N 行，输出列结构 + 可疑标记 |
| `scripts/dedupe.py` | 模糊去重（fuzzywuzzy，可指定字段权重） |
| `scripts/normalize_cn.py` | 中文常见字段标准化（城市/电话/姓名） |
